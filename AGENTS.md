# AGENTS.md

Правила для ассистентов и автоматизации в этом репозитории. `CLAUDE.md` подключает этот же файл.

## Что это

Читалка книг для телефона на Android: полка, чтение, озвучка текста голосами Google Gemini TTS. Приложение
одного пользователя (владельца), без сервера и учётных записей.

Источники правды, по старшинству:

1. код и история git;
2. [docs/WHERE_WE_ARE.md](docs/WHERE_WE_ARE.md) — что сделано и что дальше; читать первым;
3. [docs/CONCEPT.md](docs/CONCEPT.md) — что строим и чего не строим;
4. [docs/GEMINI_TTS.md](docs/GEMINI_TTS.md) — как вызывать Gemini и сколько это стоит;
5. макет интерфейса (появится в `docs/mockup/`).

Markdown отстаёт от кода. Если документ и код расходятся, прав код, а документ правится тем же коммитом.

## Принципы владельца

Перенесены из DocxAICorrector и AudiobookStudio, где каждый был оплачен ошибкой.

- **Простота.** Базовый набор функций без избыточности. Функции из раздела «Не делаем» концепции не добавлять без
  решения владельца. Краевые случаи не шлифовать, пока они не встретились на настоящей книге.
- **Интерфейс — с точки зрения читателя:** минимум элементов, ничего «на всякий случай», никаких ручных настроек
  там, где приложение может решить само.
- **Сбойный шаг проектируется так, чтобы не падать.** Временная ошибка сети или Gemini (408, 429, 5xx, таймаут)
  повторяется сама. Уведомлениями и «деградированными» ветками сбой не закрывается. Непонятная ошибка останавливает
  озвучку и показывает текст Google как есть.
- **Общие правила, а не подгонка.** Разбор книг работает по форме и структуре файла. Литералов из конкретной книги,
  списков слов и порогов, подобранных под один файл, в коде нет. Если общего правила не находится, честный ответ —
  «не строим», а не подогнанное правило.
- **Свидетельство свежее исправления.** Вывод о дефекте делается по свежему прогону или файлу, а не по памяти и не
  по старому отчёту.
- **Деньги.** Тесты никогда не обращаются к Gemini: синтез в тестах подставной. Любой платный вызов из рабочего
  окружения — только с согласия владельца. Целую книгу ради проверки не озвучивать никогда; приёмка — несколько
  абзацев или одна глава.
- **Ключи.** Ключ Gemini в приложении хранится в защищённом хранилище Android, в рабочем окружении — в `.env`.
  Ключ не печатается, не коммитится, не попадает в логи, адреса запросов и тексты ошибок.
- **Сведения о владельце и его книгах не уходят во внешние сервисы**, кроме текста абзаца, отправляемого на озвучку.

## Стек и runtime

Стек предложен в концепции (Flutter, Android) и **ждёт решения владельца**. До решения код приложения не пишется.
На 2026-11-14 в Windows нет `flutter`, `dart`, `adb`, `java`; в WSL Debian есть `java`, а `flutter`, `dart` и `adb` нет.

После утверждения этот раздел заполняется фактическими командами (установка, тесты, сборка APK) — и только после
того, как каждая запущена и отработала. Ожидаемый вид:

- канонический runtime — WSL Debian, каталог `/mnt/d/Work/Projects/AudiobookReader`
  (Windows: `D:\Work\Projects\AudiobookReader`);
- тесты, анализатор и сборка запускаются скриптами из `scripts/`, а не набранными от руки командами;
- из не-WSL shell — `wsl.exe -d Debian --cd "D:\Work\Projects\AudiobookReader" -- bash scripts/<скрипт>`.

Shell определяется первой командой (`uname`): Git Bash — `MINGW64_NT`, WSL — `Linux …WSL2`. Внутри WSL `wsl.exe`
не вкладывать. Голое `wsl` не использовать: в PATH Git Bash его может не быть.

Грабли этого рабочего места:

- `$VAR` на границе Git Bash → `wsl.exe` схлопывается в пустую строку даже в одинарных кавычках. В таких командах
  только литеральные пути и никаких циклов.
- Heredoc в Bash-инструменте агента ломается. Многострочный код пишется в файл и запускается оттуда.
- У Windows-git в Git Bash нет имени автора. Коммит идёт с `GIT_AUTHOR_NAME="Slawa Gorobets"`,
  `GIT_AUTHOR_EMAIL` владельца и теми же значениями committer; `git config` не менять.

## Проверка работы

- **Отчёт агента — заявка, а не доказательство.** «Тесты зелёные» подтверждается выводом команды, запущенной после
  последней правки.
- **Перед «всё зелёное» — `git status --porcelain`.** Непустой вывод значит, что локальный прогон не доказывает
  ничего о коммите: CI идёт на чистом checkout.
- **Неполный вывод — проблема транспорта, а не результат.** По оборванному выводу нельзя говорить ни «прошло», ни
  «упало». Сужайте селектор, а не расширяйте прогон.
- **Один прогон на дерево.** Второй «для перепроверки» параллельно не запускать.
- **Перенос ветки на свежий `main` требует повторного полного прогона.** Ни диф, ни совпадение числа тестов этого
  не заменяют.
- **Тест не должен проходить вакуумно.** Тест на правило разбора показывает обе стороны: вход, где правило
  срабатывает, и похожий вход, где оно обязано молчать.
- **То, что видно только на телефоне, проверяется на телефоне.** Фоновое воспроизведение, управление с экрана
  блокировки, гарнитура, поведение при звонке. Если устройства или эмулятора в сессии нет, так и сказать в отчёте,
  а не выводить результат из виджет-тестов.
- Окончания строк — LF (`.gitattributes`, `.editorconfig`). Проверка: `git diff --check`.

## Оркестратор и агенты

- **Главная сессия управляет агентами, а не пишет код.** Работа уровня спеки уходит агенту. Исключение — правка,
  для которой постановка дороже самой правки.
- **За оркестратором:** постановка с уже измеренными фактами и путями, слияние веток, полный прогон в главном
  дереве, проверка каждого утверждения агента по коду, приёмочное ревью.
- **Модель по уровню задачи.** Механика (копирование, подсчёт, поиск) — Haiku. Ограниченная инженерная работа
  (экран по макету, обвязка, скрипты) — Sonnet. Разборщики форматов, плеер и очередь озвучки, разбор находок
  ревью — Opus. Модель оркестратора — только оркестратору. Между двумя ступенями берётся дешёвая; поднимать, когда
  отчёт показал, что задача была не по ней.
- **Агент, который пишет, получает своё дерево** вне репозитория (`D:\Temp\claude\wt-<slug>`). Встроенная изоляция
  кладёт worktree внутрь дерева, и git отказывается. В боковом worktree `git` под WSL не работает: `.git` там —
  файл с windows-путём.
- **Параллельно идут только непересекающиеся работы.** Делить по владению файлами, а не по темам.
- **Перед удалением worktree** скопировать всё, что должно пережить его: `git worktree remove --force` стирает
  неотслеживаемые файлы.

## Спеки и приёмка

Spec Kit здесь не используется.

- Мелкая правка — сразу в `main` с прогоном тестов.
- Крупная работа (экран, разборщик формата, плеер) — короткая спека `docs/specs/NNN-<slug>.md`: решения,
  требования, критерии приёмки, «Не делаем», Changelog. Работа идёт в своей ветке. Перед слиянием — полный прогон
  зелёный и `git status --porcelain` пуст.
- **После крупной работы, до слияния в `main`, — независимое ревью Codex** по всем затронутым модулям целиком, а не
  по диффу. Рецепт — [docs/CODEX_INDEPENDENT_REVIEW.md](docs/CODEX_INDEPENDENT_REVIEW.md). Каждую находку
  оркестратор проверяет по коду сам: примерно одна из шести слабее заявленного. Находка приземляется правкой с
  тестом, записью в Changelog спеки или записанным отказом с причиной. Отчёт кладётся в
  `docs/reviews/CODEX_REVIEW_<NNN>_<дата>.md`.
- Внутренний второй проход независимым ревью не называется. Если Codex недоступен, это сказано в отчёте.
- Решение владельца записывается в спеку или концепцию в тот же день, с датой. Отклонённое предложение записывается
  в «Не делаем» — иначе оно возвращается.
- Тема коммита называет номер спеки, только если коммит — работа по ней.
- В конце работы по спеке всё влито в `main` и отправлено на GitHub.

## Интерфейс

- Макет делается в FigCraft через его MCP. Реализация сверяется с макетом, а не с памятью о нём.
- Строки интерфейса — на русском, в одном файле локализации, а не в коде экранов.
- Экран проверяется на узком телефоне и с крупным системным шрифтом.
