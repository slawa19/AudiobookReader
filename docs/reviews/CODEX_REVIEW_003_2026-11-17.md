## Codex's findings (condensed, not softened)

1. **Should fix — signing is permitted from unreviewed refs.** `.github/workflows/release.yml:33,49,64,93,108`;
   `docs/RELEASING.md:198,225`. A manual dry run on a branch receives the permanent signing key; a version-matching tag
   outside `main` also passes. Modified build scripts on that ref can read the keystore and passwords. Needs repository
   write access or a maintainer dispatch; an ordinary fork PR does not suffice. Confidence high; exfiltration is a
   forecast. Fix: protected release-environment secrets and protected tags, require release commits to belong to
   `main`, restrict signed dry runs to trusted refs; keep build/test read-only and grant publishing permissions
   separately.
2. **Should fix — the attestation command proves less than the documentation claims.** `docs/RELEASING.md:46,53,92`.
   The displayed command restricts verification only to the repository, while the later text claims `release.yml`, the
   release tag and a GitHub-hosted runner; an attestation from another workflow or ref in the same repository
   satisfies the command. Fix: make `--signer-workflow slawa19/AudiobookReader/.github/workflows/release.yml`,
   `--source-ref refs/tags/v<version>` and `--deny-self-hosted-runners` mandatory in the example; pin
   `--source-digest` when checking an expected commit.
3. **Should fix — the in-app notices omit the bundled demo-content attribution.** `pubspec.yaml:39`,
   `assets/demo/SOURCES.txt:19`, `lib/screens/licenses.dart:26`, `test/licenses_test.dart:29`, `README.md:180`. The
   license page shows the project and font entries but no Wikisource / CC BY-SA notice, although the README says the
   app shows these notices; the Russian demo assets are bundled in Android builds. Fix: register the attribution and
   license link on the license page and update the test that requires exactly three entries.
4. **Minor — Android SDK pinning is overstated.** `scripts/env.sh:22`, `scripts/setup-wsl.sh:83`,
   `docs/RELEASING.md:114`. Setup requests `platforms;android-36` without a package revision and accepts an existing
   installation if `package.xml` exists; a later SDK revision can change toolchain inputs for the same tag. Fix: record
   and validate package revisions, or narrow the documentation's claim.
5. **Minor — personal workstation information survives in reachable history.** `3a77332:AGENTS.md:82` contains the
   Windows user name and the absolute location of the permanent keystore (no keystore content). Fix: redact from
   history before publication, or record the owner's decision to publish it.
6. **Minor — the publication audit contradicts the actual history rewrite.** `docs/specs/003-open-source.md:60,88,98`
   say history was not rewritten; `AGENTS.md:132` and commit `3e73e6f` record the personal-email rewrite. Fix: update
   R7, Out of scope and the Changelog.
7. **Minor — the documented Android update restriction is incorrect.** `docs/RELEASING.md:83,207`. It says an equal
   build number prevents installation; Android's restriction concerns a lower `versionCode`. Fix: keep increasing
   build numbers as release policy but do not present it as an Android install restriction.
8. **Minor — the "no Cyrillic" test misses Ukrainian-specific letters.** `test/l10n_test.dart:34,37`. `[А-яЁё]`
   accepts a translation containing only `ЇїІіЄєҐґ`. Fix: cover the Cyrillic Unicode ranges and add a negative case.
9. **Minor — Ukrainian chapter status uses the wrong grammatical gender.** `lib/screens/l10n/app_uk.arb:78`,
   `lib/screens/toc_screen.dart:133`. `озвучена` for `розділ`; use `озвучено` or `озвучений`.

Other surfaces (licensing consistency, OFL, ARB keys and placeholders, demo-content injection) produced no findings.
