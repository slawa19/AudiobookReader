# Как вызывать Codex для независимого ревью

Перенесено из DocxAICorrector, где рецепт сложился за несколько месяцев. После крупной работы её отдают другой
модели: Codex ходит другим движком и видит то, чего не видит внутренний цикл. Там он находил настоящие дефекты в
работе, уже прошедшей три внутренних прохода.

## 1. Найти бинарь — каждый раз заново

Codex установлен на Windows-хосте. Каталог версии меняется при каждом обновлении, а `codex.exe` прямо в `bin\` —
отдельный старый билд, который падает на текущем конфиге. Нужен самый свежий из версионных подкаталогов:

```powershell
$codex = (Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\bin" -Recurse -Filter codex.exe |
          Where-Object { $_.DirectoryName -ne "$env:LOCALAPPDATA\OpenAI\Codex\bin" } |
          Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
& $codex --version
```

Модель и усилие заданы в `~/.codex/config.toml`; флаги модели не нужны.

## 2. Запустить

Промпт — всегда файлом через stdin, ответ — в файл, запуск в фоне (5–20 минут):

```powershell
Get-Content "<промпт.txt>" -Raw | & $codex exec --sandbox read-only - 2>&1 |
  Out-File -FilePath "<ответ.txt>" -Encoding utf8
```

`--sandbox read-only` — он ничего не изменит в репозитории, но команды выполнять может.

Ответ читать с конца и поиском, не целиком: Codex повторяет промпт в начале, файл выходит на тысячи строк. Итоговый
отчёт идёт после последней строки, состоящей из одного слова `codex`. Поэтому в промпте требуют вердикт одной
строкой из фиксированного набора, например `СЛИВАТЬ` / `ДОРАБОТАТЬ`.

## 3. Что он может

| может | не может |
|---|---|
| читать любой файл по абсолютному пути, включая исключённые из git | работать в WSL |
| выполнять команды, в том числе Python | запускать тесты и сборку проекта, если они живут в WSL |
| считать по данным сам | — |

Давайте ему абсолютные пути к данным и просите считать. Формулировка «ты ничего не можешь запустить» превращает
его в генератор гипотез там, где он мог бы дать факт.

## 4. Что писать в промпте

- **Диапазон:** base и head SHA, команды `git diff <base>..<head> --stat` и `git log --oneline <base>..<head>` —
  пусть выполнит сам.
- **Поверхности — не дифф.** Литеральный список абсолютных путей: каждый модуль с изменённым фрагментом целиком,
  его вызывающие и вызываемые, его тесты. Ревью одного диффа пропускает дефекты, которые правка создала в
  неизменённых строках.
- **Что делает изменение** — своими словами, и путь к спеке.
- **Правила проекта:** общие правила разбора без литералов из книг; тесты не ходят в Gemini; ключ не попадает в
  логи и тексты ошибок; простота вместо механизмов «на всякий случай».
- **Его возможности первым абзацем:** «ты в том же окружении: читай файлы по абсолютным путям и считай сам. WSL
  тебе закрыт, тесты проекта не запустишь. Не выдумывай измерений; число, которого нет в файлах, называй прогнозом
  и говори, чем его проверить».
- **Что уже измерено оператором и чем.**
- **Формат ответа:** `файл:строка` на каждую находку; при каком конкретном входе проявится; частота и чем она
  измерена, либо что это прогноз; уверенность; вердикт последней строкой.
- **Просить возражать:** «возражение с конкретной ссылкой ценнее согласия; если всё в порядке, скажи это коротко».

Слов «атакуй», «сломай», «найди дыры» не писать: срабатывает фильтр безопасности, и запрос отклоняется, потратив
контекст. Писать «проверь корректность», «анализ устойчивости».

## 5. Что делать с ответом

- **Проверить каждую находку по коду самому.** Примерно одна из шести слабее заявленного.
- **Переранжировать.** Он ранжирует рассуждением, а не частотой: редкий случай и ежедневный получают одинаковый
  приоритет.
- **Приземлить каждую:** правка с тестом, запись в Changelog спеки или записанный отказ с причиной в её «Не
  делаем». Для инструмента одного пользователя отказ — нормальный исход: находки сортируются, а не чинятся все.
- Отчёт с промптом и таблицей «поднято / вердикт / что сделано» — в `docs/reviews/CODEX_REVIEW_<NNN>_<дата>.md`.
  Источником правды он не является; им остаются спека и код.

## 6. Когда

- После крупной работы, а не после каждой задачи: все ветки влиты в интеграционную, полный прогон зелёный,
  `git status --porcelain` пуст. До слияния в `main`.
- Лучший момент — когда решение сформулировано, но ещё не построено: ревью спеки до реализации дешевле тех же
  замечаний после неё.

## 7. Если Codex недоступен

Честных вариантов три: владелец запускает промпт сам; работа продолжается без ревью, и это сказано в отчёте
вслух; владелец решает ставить Codex иначе. Внутренний второй проход независимым ревью не называется — вся
ценность в другом движке.
