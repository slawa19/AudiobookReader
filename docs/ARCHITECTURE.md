# Архитектура

Версия 1 от 2026-11-14, до ревью. Описывает первую версию приложения из [CONCEPT.md](CONCEPT.md): Flutter,
Android, один пользователь. Пометка **[замер]** стоит там, где число или выбор ждут измерения на этапе 0; до него
это прогноз.

Названия пакетов — кандидаты. Версии и сам выбор подтверждаются при установке по актуальной документации; замена
пакета архитектуру не меняет, потому что каждый спрятан за своим модулем.

## 1. Главные решения

| № | Решение | Почему |
|---|---|---|
| A1 | Одна модель книги для всех форматов | экран, озвучка и позиция не знают о форматах; новый формат — один разборщик |
| A2 | Разбор один раз при добавлении, результат хранится файлом | открытие книги не зависит от размера и капризов исходника |
| A3 | Базы данных нет: папка на книгу, в ней JSON-файлы | на полке десятки книг; нет схемы, миграций и генерации кода |
| A4 | Текст рисует приложение, страницы считаются по главе | нужно знать, какой абзац на экране, подсвечивать его и листать вслед за голосом |
| A5 | Единица озвучки — отрезок: абзац или его часть по границам предложений | один механизм закрывает и предел Gemini на длину, и задержку до первого звука |
| A6 | Звук отрезка хранится под именем-отпечатком текста и профиля голоса | повтор бесплатен; смена голоса не путает старое с новым |
| A7 | Плеер играет готовые файлы; очередь синтеза держит запас впереди | сеть и Gemini отвязаны от воспроизведения; сбой сети не слышен, пока есть запас |
| A8 | Всё платформенное — в одном модуле | остальное проверяется в WSL без телефона |
| A9 | Без фреймворков состояния и внедрения зависимостей | три экрана и один плеер; хватает `ChangeNotifier` и передачи в конструктор |

## 2. Модули

Один пакет Flutter, каталоги в `lib/`. Стрелки — разрешённые зависимости; обратных нет.

```
app ──► screens ──► reader ──► book
              │
              ├───► playback ──► tts
              │          │─────► audio
              │          └─────► book
              └───► library ──► book
platform  ◄── playback, audio, library   (только через интерфейсы из этих модулей)
```

| Модуль | Отвечает за | Не знает о |
|---|---|---|
| `book` | модель книги, разборщики FB2 / EPUB / TXT, определение формата и кодировки | Flutter, файловой системе приложения |
| `library` | полка: добавление, удаление, папки книг, позиция, настройки, учёт расхода | экранах, плеере |
| `reader` | разбивка главы на страницы, отрисовка страницы, подсветка | озвучке, сети |
| `tts` | клиент Gemini, профиль голоса, отпечаток, деление на отрезки, классы ошибок, подставной синтез | плеере, файлах |
| `audio` | хранилище звука отрезков: записать PCM, отдать файл, посчитать и очистить место | Gemini, книге |
| `playback` | состояние прослушивания, очередь синтеза, связь с плеером и медиасессией | отрисовке |
| `screens` | полка, чтение, оглавление, голос, настройки | HTTP, форматах |
| `platform` | всё, что требует Android: кодировщик звука, приём файла из другого приложения | логике приложения |
| `app` | сборка зависимостей, маршруты, тема, строки | — |

`book` и `tts` — чистый Dart без Flutter: их тесты самые быстрые и самые важные.

## 3. Модель книги

```
Book      { id, title, author, language, chapters[], parserVersion, totalChars }
Chapter   { title, level, firstBlock, blockCount }
Block     { index, kind, text, spans[], imageId?, noteId? }
  kind:   heading | paragraph | image | verse | cite | separator
Span      { start, end, style: italic | bold | sup | sub | noteRef(noteId) }
Note      { id, blocks[] }
```

- **Блоки пронумерованы сквозь книгу**, номер постоянен для данного `parserVersion`. Глава — диапазон блоков, а не
  отдельное дерево: оглавление вложенное, а чтение линейное.
- **Текст блока — обычная строка без разметки**; начертания лежат отдельно диапазонами. Озвучка берёт строку как
  есть, экран накладывает диапазоны.
- **Сноски лежат отдельно от основного потока.** В блоке остаётся ссылка-диапазон; вслух ни ссылка, ни сноска не
  читаются.
- **Вслух читаются** `heading`, `paragraph`, `verse`, `cite`. Не читаются `image` с подписью, `separator`, сноски,
  оглавление из файла книги, служебные разделы FB2 (`description`).
- Таблицы в первой версии превращаются в абзацы по строкам; отдельного вида блока нет.

**Определение формата — по содержимому, не по расширению**: ZIP с `mimetype` EPUB; ZIP с единственным `.fb2`
внутри; XML с корнем `FictionBook`; иначе текст. Кодировка FB2 берётся из объявления XML; TXT — UTF-8 с BOM или
валидный UTF-8, иначе windows-1251. Файл с DRM (EPUB с `encryption.xml` для содержимого) отклоняется с прямым
сообщением.

**Разборщик терпим к грязным файлам** общими правилами: незакрытый тег, неизвестная сущность, неверно объявленная
кодировка не роняют разбор всей книги. Что именно ломается в настоящих файлах — выясняется на книгах владельца
(раздел 9), а не придумывается заранее.

## 4. Хранение

Папка приложения, недоступная другим приложениям:

```
books/<bookId>/
  original.<ext>     исходный файл как добавлен
  book.json          модель книги (раздел 3)
  meta.json          название, автор, число знаков, есть ли обложка — всё, что нужно полке
  state.json         позиция, свой голос книги, время последнего открытия
  cover.jpg
  images/<imageId>
  audio/<отпечаток>.<расширение>
usage.json           оплаченные токены по месяцам и моделям
```

- `bookId` — первые 12 знаков sha256 исходного файла. Тот же файл второй раз не добавляется, а открывается.
- Полка читает только `meta.json` и `state.json` каждой папки.
- `state.json` и `usage.json` пишутся во временный файл с переименованием: недописанного файла не бывает.
- Удаление книги — удаление папки. «Очистить озвучку» — удаление папок `audio/`.
- Настройки приложения (голос, модель, тема, размер шрифта) — в обычном хранилище настроек; ключ Gemini — в
  защищённом (`flutter_secure_storage`), из резервного копирования Android исключён.

**Исходник хранится, чтобы переразобрать книгу после исправления разборщика.** `parserVersion` в `book.json`
старше текущего → книга разбирается заново при открытии. Номера блоков при этом могут сдвинуться, поэтому позиция
хранит ещё и число знаков от начала книги и после переразбора восстанавливается по нему. Озвучка переразбор
переживает сама: она привязана к тексту, а не к номерам.

## 5. Чтение

- **Страницы считаются для одной главы** при входе в неё, измерением текста средствами Flutter. Страница — пара
  «начало: блок и смещение» и «конец». Абзац переносится между страницами по строке.
- **Сквозной нумерации страниц нет**: она требует разбить всю книгу заранее и пересчитывать при каждой смене
  шрифта. Показываются доля книги по знакам и «страница N из M в главе».
- Смена шрифта, темы или поворот пересчитывают только текущую главу и открывают страницу с сохранённой позицией.
- Переносов по слогам в первой версии нет; выравнивание по левому краю.
- **Позиция** — `{block, offset, charsBefore}`. При чтении это начало первой строки на экране; при прослушивании —
  начало звучащего отрезка. Сохраняется при перелистывании и при смене отрезка, не чаще раза в секунду.
- **Следование за голосом.** Пока звучит озвучка, экран показывает страницу со звучащим отрезком и подсвечивает
  его блок. Если пользователь листает сам, следование отключается до нажатия «К месту чтения» или до паузы и нового
  старта; голос при этом не прерывается.

## 6. Озвучка

### 6.1 Отрезок

Отрезок — то, что уходит одним запросом и ложится одним файлом: блок целиком, если он не длиннее `L` знаков, иначе
его куски по границам предложений не длиннее `L`. Деление — чистая функция от текста блока и `L`, поэтому тот же
блок всегда даёт те же отрезки.

`L` **[замер]**: стартовое значение 600. Верхняя граница — 4 000 (предел Gemini на 655 с звука с запасом). `L`
подбирается так, чтобы запрос на первый отрезок укладывался в терпимое ожидание после нажатия «Слушать».

Короткие абзацы не объединяются в один запрос. Объединение зависело бы от того, с какого абзаца начали слушать, и
ломало бы повторное использование звука. Отставание на диалогах из коротких реплик закрывается запасом и
параллельными запросами (6.3).

### 6.2 Клиент и отпечаток

Форма запроса, голоса, пределы, классы ошибок и тарифы — [GEMINI_TTS.md](GEMINI_TTS.md); клиент повторяет
проверенный в студии.

```
TtsEngine.synthesize(text, profile) → { pcm, sampleRate, audioTokens, inputTokens? }
  ошибки: TemporaryTtsError (408, 429, 5xx, таймаут, сеть) | TtsError (остальное; у 402 — ссылка на пополнение)
VoiceProfile { model, voiceId, style }
fingerprint(text, profile, audioFormat) → sha256
```

- Клиент сам не повторяет запросы: временную ошибку он только помечает, повторяет очередь.
- Перед отправкой из текста снимается знак ударения U+0301.
- `FakeTtsEngine` отдаёт тон длиной, пропорциональной тексту. Им пользуются все тесты и разработка экранов.
- Идентификаторы моделей, список голосов, тарифы с датой проверки — в одном файле модуля `tts`.

### 6.3 Очередь синтеза

Очередь знает текущий отрезок и держит впереди него готовый звук.

- **Запас меряется секундами звука, а не числом отрезков**: десять реплик диалога и десять длинных абзацев — разный
  запас. Синтез идёт, пока готового звука впереди меньше цели, и стоит, когда больше. Цель **[замер]**: стартовое
  значение 120 с.
- Одновременно до двух запросов **[замер]**; порядок в плеере сохраняется независимо от порядка ответов.
- Перед запросом очередь смотрит в хранилище: готовый отрезок не синтезируется.
- **Пауза останавливает очередь**: идущий запрос доводится до конца и сохраняется, новые не начинаются. Деньги не
  уходят на то, что не слушают.
- **Временная ошибка** повторяется с растущей задержкой до 30 с, пока пользователь слушает. Пока есть запас, её не
  видно. Когда запас кончился — состояние «Жду связь», которое само сменяется воспроизведением.
- **Постоянная ошибка** останавливает прослушивание на границе готового звука и показывает текст Google; у 402 —
  кнопка «Пополнить». Позиция при этом — первый неозвученный отрезок, и «Слушать» продолжает с него.
- Смена голоса или модели во время прослушивания сбрасывает запас и начинает с текущего отрезка новым профилем.
- Оплаченные токены каждого ответа добавляются в `usage.json`.

### 6.4 Хранилище звука

```
AudioStore.has(fingerprint) / file(fingerprint) / put(fingerprint, pcm, sampleRate) / sizeOf(book) / clear(book)
```

Gemini отдаёт PCM 24 кГц моно — около 170 МБ на час; книга заняла бы гигабайты. На телефоне звук сжимается
системным кодеком Android через модуль `platform`. Кодек **[замер]**: AAC в контейнере M4A, если проверка на слух
и на стыках файлов не покажет иного. Формат входит в отпечаток, поэтому смена кодека не выдаёт старые файлы за
новые.

Для тестов и для Linux есть реализация без сжатия (WAV) — тот же интерфейс.

### 6.5 Воспроизведение

- Плеер (`just_audio`) играет список файлов; очередь дописывает в него готовые отрезки. У каждого элемента списка
  — номер отрезка; смена текущего элемента двигает позицию, подсветку и страницу.
- Медиасессия (`audio_service`): служба переднего плана с уведомлением, экран блокировки, кнопки гарнитуры. Звонок,
  чужой звук и вынутые наушники ставят паузу (`audio_session`).
- **Служба становится активной с момента нажатия «Слушать»**, а не с первого звука: иначе Android может остановить
  приложение, пока оно ждёт первый ответ Gemini при погашенном экране.
- Скорость меняет плеер. «Назад» и «вперёд» переходят к началу предыдущего и следующего блока.
- Между блоками плеер выдерживает короткую паузу; её длина подбирается на слух **[замер]**.
- Таймер сна — пауза по времени или по концу главы.

`NarrationController` — единственное место, где сходятся очередь, плеер и позиция. Его состояния:

```
idle → preparing → playing ⇄ paused
            │          │
            │          ├─► waiting   (запас кончился, идут повторы) ─► playing
            │          └─► stopped   (постоянная ошибка или конец книги)
            └─► stopped
```

Экран подписан на состояние и ничего не решает сам.

### 6.6 «Скачать главу»

Та же очередь с целью «до конца главы» вместо запаса. В первой версии работает, пока приложение на экране; экран
на это время не гаснет. Ушли из приложения — остановилась, вернулись — продолжает с первого неозвученного отрезка.
Фоновая загрузка без воспроизведения потребовала бы отдельной службы Android с собственными ограничениями; она не
строится, пока не понадобится.

## 7. Платформа

Модуль `platform` — единственное место с кодом на Kotlin и каналами к нему:

- кодировщик PCM → сжатый файл (`MediaCodec` + `MediaMuxer`);
- приём файла от другого приложения («Открыть с помощью») и из системного выбора файла; файл сразу копируется в
  папку книги, постоянные права на исходник не запрашиваются.

Разрешения: интернет, уведомления (Android 13+), служба переднего плана для воспроизведения. Доступа к общей
памяти, контактам, местоположению нет. Незашифрованный HTTP запрещён; приложение обращается только к
`generativelanguage.googleapis.com`.

Минимальная версия Android определяется телефоном владельца **[решение владельца]**.

## 8. Экраны и состояние

- Маршруты: полка → чтение; поверх чтения — оглавление, голос, сноска; настройки с полки.
- На экран — один контроллер (`ChangeNotifier`): `ShelfController`, `ReaderController`. `NarrationController` и
  `Library` живут всё время работы приложения и создаются в `app`.
- Зависимости передаются в конструкторы. Генерации кода нет: чтение и запись JSON для нескольких классов написаны
  руками.
- Строки интерфейса — в одном файле локализации.
- Разбор книги при добавлении идёт в отдельном изоляте: полка не замирает.

## 9. Проверка

| Что | Чем | Где |
|---|---|---|
| разборщики, деление на отрезки, отпечаток, клиент Gemini на записанных ответах | модульные тесты | WSL, CI |
| разбивка на страницы | тесты со встроенным шрифтом | WSL, CI |
| экраны, очередь и состояния прослушивания | виджет-тесты с `FakeTtsEngine` и подставным плеером | WSL, CI |
| вид экранов против макета | снимки экранов, только на Linux | WSL, CI |
| фон, экран блокировки, гарнитура, звонок, «Открыть с помощью», кодек | список ручной проверки `docs/DEVICE_CHECKLIST.md` | телефон владельца |

- Тесты не обращаются к Gemini. Клиент проверяется на ответах, записанных по форме из студии.
- Образцы книг в `test/fixtures/` — собственные маленькие файлы на каждое правило разбора, с парой «срабатывает /
  обязано молчать». Чужие книги в репозиторий не кладутся.
- Настоящие книги владельца лежат в `test/local_books/` (вне git). Дымовой тест разбирает каждую и пропускается,
  если папки нет.
- CI: анализатор, тесты, сборка APK как проверка того, что проект собирается.
- **APK для телефона собирается локально одним постоянным ключом подписи**, который хранится вне репозитория.
  Сборки CI подписаны другим ключом и поверх установленного приложения не ставятся.

## 10. Чего в архитектуре нет намеренно

- Базы данных, слоя репозиториев поверх файлов, миграций.
- Фреймворка состояния, контейнера зависимостей, генерации кода.
- Встроенного браузера для показа книги.
- Второго движка озвучки. `TtsEngine` — интерфейс ради подставного синтеза в тестах; системный голос Android
  отклонён владельцем для первой версии.
- Потокового ответа Gemini. Если замер покажет, что и при малом `L` ждать первого звука долго, это отдельная
  спека: меняется клиент и хранилище, но не очередь и не плеер.
- Объединения коротких абзацев в один запрос (6.1).
- Фоновой загрузки главы без воспроизведения (6.6).
- Аналитики, отчётов о сбоях, сетевых обращений кроме Gemini.

## 11. Что ждёт замера на этапе 0

| Что | От чего зависит |
|---|---|
| время запроса на отрезок в 100, 300, 800 знаков; обе модели | `L` (6.1) |
| отношение времени синтеза к длительности звука, в том числе на мобильной сети | цель запаса и число параллельных запросов (6.3) |
| поведение Gemini на очень коротком тексте («— Да.») | нужен ли нижний порог длины отрезка |
| кодек: качество на слух, размер, стыки файлов | формат хранилища (6.4) |
| живёт ли служба при погашенном экране на телефоне владельца, пока идёт ожидание | 6.5 |
